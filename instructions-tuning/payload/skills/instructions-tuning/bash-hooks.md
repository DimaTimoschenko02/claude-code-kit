# Пишешь bash-хук — чеклист

Диагноз сказал «это детерминизм → хук». Дальше класс дефектов смещается: правило верное,
ломается реализация. Каждый пункт ниже выведен из реального срабатывания хука, это не гигиена вообще.

1. **stdin парсить только `jq`.** Жадный `sed` по JSON захватил хвост с `session_id`, и проверка
   темы срабатывала всегда, независимо от текста промпта.
2. **Отсечь системные события.** `<task-notification>` и `[SYSTEM NOTIFICATION]` приезжают тем же
   каналом, что промпт пользователя: хук выстрелил по собственному выводу агента.
   `case "$prompt" in *'<task-notification>'*) exit 0 ;; esac`
3. **Состояние — per-session файл, не общий.** Параллельные окна — норма: чужой SessionStart
   затирал общий маркер и сбрасывал гейт посреди работы.
4. **Свежесть контекста меряется reset-файлом, не wall-clock TTL.** Окно «2 часа» истекало
   посреди работы; `/clear` и `/compact` выносят текст из контекста, а `resume` — нет,
   и время об этом ничего не знает. Читай reset-маркер, а не часы.
5. **Вывод человеку ≤3 строк.** Инструкции, положенные в `reason`, уезжают человеку в чат.
   Детали — в файл рядом, в сообщении ссылка.
6. **Regex: границы слов + тела heredoc — данные.** Хук принимал примеры команд внутри heredoc за исполняемые
   команды. Исключение — тело, которое выполняет shell (`bash <<EOF`, `ssh host <<EOF`): там команды настоящие.
   В JS `\b` знает только ASCII — после кириллицы граница не срабатывает никогда, паттерн молча мёртв;
   нужен `(?![\p{L}\p{N}])` с флагом `u`.
7. **Не писать состояние внутрь рабочего репо.** Хук клал файлы в `.claude/state/` репозитория и
   ломал собственную проверку чистоты дерева. Стейт — в `<workspace>/.claude/state/`.
8. **Тест обязателен в обе стороны, до подключения:** срабатывает на целевом случае и молчит на
   соседнем. Половина списка выше — «сработало, когда не должно», и ловится только вторым тестом.
   Проверь и сам факт подключения: `settings.json` валиден, хук висит на нужном событии.
9. **Текст, который хук кладёт в контекст, — тоже инструкция.** Тот же бюджет и те же правила
   записи (`SKILL.md`, шаги 3–4): без капса, причина вместо нажима. Класть его сообщением
   (`additionalContext`), а не менять посреди сессии набор тулзов или модель — это сбрасывает
   кэш промпта на всю беседу.
