# Точка останова — формат

Файл пишется перед сжатием контекста и после него возвращается в контекст рядом с резюме компакта.
Авто-компакт без свежей точки откладывается (мод `stop-point`); ручной `/compact` владелец делает сам, попросив точку.

## Писать только то, что резюме теряет

Резюме компакта само несёт: все сообщения владельца дословно, что сделано по файлам,
открытые задачи, текущую работу и следующий шаг. Это сюда не повторять: двойной текст
после сжатия и есть лишние токены. Резюме теряет в первую очередь URL, числа, причины
отказов. Список прочитанных и правленных файлов после сжатия подложит мод — его тоже не писать.

- **Опоры.** Ссылки на доки, записи памяти, `file:line`, на которых держатся выводы, —
  по строке с тем, что там лежит. Всё, за чем иначе придётся идти искать заново.
- **Значения.** Число — что оно меряет и откуда взято (скрипт, замер, дата). Идентификаторы:
  хеши, id сессий, порты, пути стендов.
- **Действующие вердикты.** Какое решение владельца отменило прежнее (цитатой) и что
  отвергнуто — с причиной, иначе после сжатия это предложат снова.
- **Сейчас** — одна строка: на чём остановился, если резюме может понять это иначе.

## Правила

- Перезаписывать файл целиком, одним Write. Состояние на сейчас: устаревший вывод
  удалить, а не копить рядом с новым.
- Пустые разделы пропускать. Как искали, тупики поиска, пересказ работы — не писать.
- Долговременное знание (устойчивый факт, решение владельца с причиной) — туда, где проект
  держит долговременную память (CLAUDE.md проекта говорит где); сюда только ссылкой.
- Закончив, последней строкой сообщения, отдельным блоком после горизонтальной
  черты, ровно в таком виде и ничего после:

```
---
💾 **Точка останова записана** — `<путь к файлу>`
```
